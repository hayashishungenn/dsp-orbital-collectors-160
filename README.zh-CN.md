# 一颗气巨星装下 160 台轨道采集器

[English](README.md) · **中文**

可直接粘贴的蓝图，加上一份把它算明白的计算书：戴森球计划 **0.10.35**，一颗气巨星上 **4 圈 × 40 台 = 160 台**轨道采集器。

| | |
|---|---|
| 采集器数量 | **160**（物品 `2105`，模型 `117`） |
| 圈数 | 4 圈 —— 纬度 **0.0° / 7.2° / 14.4° / 21.6°** |
| 每圈 | **40 台**，间隔 **9°**（10 个格点） |
| 轨道半径 | **220.2**（`localOffset_z = 15.0`） |
| 最近邻间距 | **32.13 – 32.58**（均值 32.32） |
| 蓝图区域 | 1 个区域，396 × 25 格，80 个经度段 |
| 文件 | [`blueprints/160_orbital_collectors.txt`](blueprints/160_orbital_collectors.txt) |

---

## 一、前置条件

* 戴森球计划 **0.10.35.x**
* **[BlueprintTweaks](https://thunderstore.io/c/dyson-sphere-program/p/kremnev8/BlueprintTweaks/)**，且 `bpOnGasGiants = true`

  原版是**禁止在气巨星上贴蓝图**的：`BuildTool_BlueprintPaste.CheckBuildConditionsPrestage()` 一旦发现 `planet.gasItems != null`（气巨星必然如此）就直接 `EBuildCondition.Failure` 返回。BlueprintTweaks 改的正是这个方法（配置项 `bpOnGasGiants`，默认 `true`），没有它这个文件贴不上去。

  ```ini
  # BepInEx/config/org.kremnev8.plugin.BlueprintTweaks.cfg
  [Misc]
  bpOnGasGiants = true
  ```

蓝图内容**只有轨道采集器**，不含任何 mod 建筑、配方或地基改造数据，所以不依赖其他 mod。

## 二、安装

把文件放进蓝图目录（子文件夹随意）：

```
%USERPROFILE%\Documents\Dyson Sphere Program\Blueprint\160 轨道采集器\
    160_orbital_collectors.txt
```

重新打开游戏内的蓝图库即可看到。

## 三、使用

1. 飞到目标气巨星；
2. 打开蓝图库，选中 **160 Orbital Collectors**；
3. 进入粘贴模式，光标对准**赤道**；
4. 必要时旋转，让选框沿**东西方向**，粘贴。

4 圈会一次落地：第一圈落在你瞄准的纬度，另外三圈依次向北。

## 四、计算书

### 4.1 气巨星网格

| 量 | 值 |
|---|---|
| 行星半径 `realRadius` | 200 |
| 赤道经度段数 | 80 |
| 每段格点数 | 5 |
| 一整圈格点数 | 80 × 5 = **400** |
| 单格角宽 | 360° / 400 = **0.9°** |
| 单格纬向高度 | **0.9°** |
| 蓝图里的轨道高度 | `z = 15.0` |
| 轨道半径 | `15.0 × 1.3333 + 0.2 + 200 =` **220.2** |

游戏把建筑存成极坐标网格：`localOffset_x` 是经度格数、`localOffset_y` 是纬度格数，半径由 `r = localOffset_z × 4⁄3 + 0.2 + realRadius` 还原。160 台全部 `z = 15.0`，因此**都在同一个 220.2 的轨道壳上**，不存在高低差。

### 4.2 为什么一圈正好 40 台

同一圈上相邻两台采集器的最小间隔是 **10 个格点**（两个"大格"，1 大格 = 5 格）。

```
一圈 400 格
──────────  = 40 台
每台占 10 格
```

换成角度：`40 × 9.0° = 360.0°`——正好闭合，既不留空档，也没有任何一对低于间距下限。**40 是这一圈的容量上限，不是随手取的数。**

### 4.3 叠圈：4 × 40 = 160

四圈按 8 格（7.2°）纬向间距往上叠，并且**相邻圈错开半个步长**：

| 圈 | 纬度 | 纬向偏移 | 起始经度 | 步长 | 台数 |
|---|---|---|---|---|---|
| 第 1 圈 | 0.0° | 0 格 | 0.0° | 9° | 40 |
| 第 2 圈 | 7.2° | 8 格 | 4.5° | 9° | 40 |
| 第 3 圈 | 14.4° | 16 格 | 0.0° | 9° | 40 |
| 第 4 圈 | 21.6° | 24 格 | 4.5° | 9° | 40 |

8 格 = `8 × 0.9° = 7.2°`；相邻圈之间那 5 格（4.5°）的错位，就是下面要算的关键。

### 4.4 间距——真正的证明

在半径 220.2 的球面上：

| 指标 | 数值（世界单位） |
|---|---|
| 第 1 圈周长 | 1383.6 |
| 第 2 圈周长 | 1372.6 |
| 第 3 圈周长 | 1340.1 |
| 第 4 圈周长 | 1286.4 |
| 各圈圈内间距（1/2/3/4） | 34.55 / 34.28 / 33.47 / 32.13 |
| 相邻圈最近距离（1↔2 / 2↔3 / 3↔4） | 32.58 / 32.43 / 32.15 |
| **全局最近邻** | **最小 32.13，最大 32.58，均值 32.32** |

**为什么要错开半格。** 如果不做 4.5° 错位，相邻两圈最近的一对就是正南正北的正交距离：

```
2 × 220.2 × sin(7.2° / 2) = 27.66
```

27.66 明显小于圈内的 34.55——壳层会在圈与圈之间被"夹扁"。把每隔一圈平移 5 格之后，跨圈最近的一对变成对角关系：

```
Δ纬度 = 7.2°，Δ经度 = 4.5°  →  32.58
```

于是整个壳层几乎是均匀的：任意一台采集器到它最近的邻居都在 32.13 ~ 32.58 之间。这是设计出来的，不是碰巧。

### 4.5 合计

```
4 圈 × 40 台   = 160 台
全部 r = 220.2  → 同一轨道壳，无上下干涉
纬度跨度        = 0.0° ~ 21.6°（贴图框 25 格高）
```

## 七、说明与边界

* 这个文件是从**真实存档里原样复制出来的**——那 160 台当时就立在气巨星上，所以它既是纸面计算也是实测。那份存档带 mod；纯原版能否接受四圈布局，这里**没有**单独验证。最坏情况是粘贴时报错、不消耗任何材料。
* 社区 wiki 至今写着"只能放赤道、每颗最多 40 台"。请把那句理解成"单圈朴素摆法"，而不是引擎上限——本仓库的文件已经证明四圈摆得下。
* 务必保持 `bpOnGasGiants = true`，否则游戏会直接拒绝粘贴并给一个笼统的失败提示。
